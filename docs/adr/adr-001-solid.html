ADR 1

Every new class respects SOLID

Status
Accepted

Context

The portfolio is meant to demonstrate software engineering skills, not only to look good. Code structure is part of what a reviewer will read. Classes are expected in places with real behaviour, such as the seasonal background engine.

Decision

Every new class must respect the SOLID principles:

  • S — a class has a single reason to change.
  • O — extend behaviour by adding code, not by editing existing classes.
  • L — subtypes are usable wherever their base type is expected.
  • I — small, focused interfaces rather than one large contract.
  • D — depend on abstractions; dependencies are injected.

Consequences

  • The project uses erasableSyntaxOnly: no enum and no constructor parameter properties. Declare fields explicitly and use union types.
  • This applies to classes only. React function components and pure functions are not forced into classes.
  • Avoid over-engineering: a simple portfolio does not need an abstraction per file.
